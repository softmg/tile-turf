# Tile Turf

Tile Turf - браузерная изометрическая игра про контроль территории. Игрок и боты прыгают по полю 8x8, закрашивают плитки своими цветами, собирают сундуки для начисления очков и проходят кампанию из 10 уровней.

Проект построен на React 19, TanStack Start/Router, Vite, Tailwind CSS v4 и Pixi.js v8.

## Игровой процесс

- Перемещайтесь по соседним плиткам, чтобы закрашивать их своим цветом.
- Собирайте сундуки, чтобы превратить текущие закрашенные плитки в накопленные очки раунда.
- В HUD сначала показаны накопленные очки, а текущие закрашенные плитки отображаются меньшим значением `+N`.
- Каждый уровень играется до 3 побед в раундах: если первым до 3 побед доходит игрок, уровень пройден; если бот, уровень провален.
- Количество ботов растет по уровням:
  - уровни 1-2: 1 бот
  - уровни 3-4: 2 бота
  - уровни 5-7: 3 бота
  - уровни 8-10: 4 бота
- Скорость ботов увеличивается с каждым уровнем.
- Прогресс хранится в `localStorage` по ключу `iso_unlocked_level`.

## Управление

- Клавиатура: `WASD` или стрелки.
- Touch/pointer: потяните по игровой области, чтобы использовать экранный джойстик.
- На сенсорных устройствах доступен pinch-to-zoom двумя пальцами.
- В левом нижнем углу есть отдельные элементы управления масштабом.
- Кнопка настроек в правом верхнем углу ставит игру на паузу, продолжает раунд и открывает обучение.

## Предметы и опасности

- Сундук: начисляет очки за текущие закрашенные плитки персонажа, очищает эти плитки и появляется в другом месте.
- Ботинки: временно ускоряют передвижение.
- Бомба: показывает предупреждение 2 секунды, затем взрывается на своей плитке. Попадание оглушает персонажа и очищает все плитки, которыми он владел.
- Вращающаяся стрелка: закрашивает линию от своей плитки в направлении, которое было активно в момент срабатывания.

## Технологии

- Runtime и пакетный менеджер: Bun
- UI: React 19
- Роутинг и SSR: TanStack Start и TanStack Router
- Рендеринг игры: Pixi.js v8
- Стили: Tailwind CSS v4 с CSS-переменными
- UI-примитивы: Radix UI и локальные компоненты `src/components/ui/*`
- Иконки: Lucide React
- Сборка: Vite через `@lovable.dev/vite-tanstack-config`
- Целевая платформа деплоя: Cloudflare Workers через `wrangler.jsonc`

    rng.ts                Детерминированный seeded RNG

  routes/

## Архитектура игры

Основная игра сейчас находится в `src/components/IsoGrid.tsx`.

`IsoGrid` отвечает за меню уровней, прогресс разблокировки, обучение, счет побед в матче, состояния прохождения/провала и историю раундов.

`IsoRound` владеет Pixi-приложением и активным игровым циклом. В нем создаются поле, персонажи, миникарта, HUD, предметы, опасности, камера, клавиатурное управление, touch-джойстик, масштабирование, AI ботов, обновление счета и teardown.

Часть чистой логики уже вынесена в `src/game/*`:

- константы поля и масштабирование уровней
- изометрическая математика
- детерминированная случайность
- подсчет очков
- helpers для `localStorage`
- типы сущностей и опасностей

При изменении gameplay лучше выносить новые чистые хелперы в `src/game`, а не увеличивать `IsoGrid.tsx`.

## Заметки для разработки

- Используйте Bun, потому что в репозитории есть `bun.lock`.
- `vite.config.ts` делегирует большую часть настройки в `@lovable.dev/vite-tanstack-config`. Не добавляйте туда дублирующие плагины TanStack, React, Tailwind, alias или Cloudflare.
- `src/server.ts` оборачивает server entry TanStack Start и превращает критические SSR-сбои в брендированную error page.
- `src/start.ts` добавляет request middleware с той же страницей ошибки для неожиданных server-side исключений.
- Pixi renderer ограничивает device pixel ratio на coarse-pointer устройствах, чтобы снизить нагрузку на мобильных.
- Обновления счета в React throttled, чтобы Pixi game loop не вызывал лишние HUD re-render.
- Для новых детерминированных gameplay-тестов используйте seeded RNG из `src/game/rng.ts`, а не прямой `Math.random()`.

## Debug и test hooks

Отдельного автоматизированного игрового test suite пока нет. Пока раунд смонтирован, компонент выставляет в браузере два хука:

```js
window.render_game_to_text();
window.advanceTime(ms);
```

Эти хуки предназначены для детерминированных browser smoke tests. Откройте игру с `?manualTicker=1` или заранее выставьте `window.__HOP_AND_FILL_MANUAL_TICKER__ = true`, чтобы Pixi ticker не соревновался с ручным временем. `advanceTime(ms)` продвигает общий gameplay loop шагами до 50 мс и возвращает текстовое представление поля.

В dev-сборке кнопка `DBG` в левом нижнем углу включает performance overlay: FPS, время кадра, частоту покраски, работу миникарты, число анимаций, бомб и активных ботов.

## Проверка изменений

Для изменений только в документации обычно достаточно проверить `git diff`.

Для gameplay, UI или rendering-изменений:

1. Выполните `bun run build`.
2. Выполните `bun run lint`, если задача не избегает отдельного форматирующего прохода.
3. Запустите `bun run dev`.
4. Откройте меню уровней.
5. Запустите уровень.
6. Проверьте движение с клавиатуры.
7. Проверьте touch/pointer-управление, если изменение его касается.
8. Поставьте игру на паузу и продолжите.
9. Соберите или дождитесь предмета/опасности, если изменение касается gameplay.
10. Проверьте browser console на ошибки.

## Persistence

Игра хранит небольшое состояние на клиенте в `localStorage`:

- `iso_unlocked_level`: максимальный разблокированный уровень кампании, clamped в диапазоне 1-10.
- `isogrid:tutorial:v1`: флаг, что обучение уже было закрыто.

## Deployment

В проекте есть `wrangler.jsonc` для Cloudflare Workers. Cloudflare-сборка подключается через `@cloudflare/vite-plugin` внутри Lovable TanStack Vite config. Worker entry настроен на `src/server.ts`.

Перед деплоем выполните production build:

```bash
bun run build
```
